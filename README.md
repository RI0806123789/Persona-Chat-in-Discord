# Persona Chat in Discord

## 🛠️ 技術スタック

![Python](https://img.shields.io/badge/Python-3.10%2B-3776AB?style=for-the-badge&logo=python&logoColor=white)

Google Gemini を使い、ペルソナ（キャラクター）になりきって会話する Discord ボットです。テキストチャット・ボイスチャンネルでの読み上げ・長期記憶・リマインダーなどの機能を備えています。

開発への参加・バグ報告・機能提案は [貢献ガイド](CONTRIBUTING.md) を、参加時のルールは [行動規範](CODE_OF_CONDUCT.md) を参照してください。脆弱性は [セキュリティポリシー](SECURITY.md) の窓口へ報告してください。

> **⚠️ フィクションに関する免責事項**
>
> ペルソナはすべて**架空のキャラクター**です。性格・口調はエンターテインメント目的のロールプレイ指示であり、実在の人物・団体・属性を表現・差別・攻撃する意図は一切ありません。ボットの出力は AI による創作で、開発者の見解を反映するものではありません。

## ✨ 機能一覧

| 機能 | 概要 |
| --- | --- |
| AI チャット | メンション（設定で全発言）に Gemini が応答する。画像・文書（pdf / txt / csv / md）の添付にも対応 |
| キャラ設定 | ペルソナ 12 種・モデル 3 種・応答モードの切り替えと、チャンネルの会話リセット |
| 長期記憶 | 会話の内容を覚えて回答に使う。記憶はユーザーごとに完全に分離される |
| Google 検索 | 最新の情報を検索し、回答に参考リンクを付ける（ON/OFF 切り替え可） |
| 音声読み上げ | `/join` または自律行動でボイス接続中に返信を読み上げる。声（話者・高さ・速さ・音色）はペルソナごとに変わる。FFmpeg 不要 |
| 会話要約 | チャンネルの会話を、発言者名つきの議事録にまとめる |
| 会話統計 | 発言回数・時間帯・話題・性格推定をグラフで表示する（本人だけに表示。収集の停止・削除も可） |
| 自発的な会話 | 会話が途絶えたチャンネルへ、ボットから話題を振る |
| 自律行動（ボイス/ステージ配信）(BETA) | ボットが自分からボイス/ステージチャンネルへ入り、独り言を続けながらコメントに応答する |
| リマインダー | 会話で頼むと、指定した時刻に通知する（毎日・毎週・毎月の繰り返しも可） |
| 記念日のお祝い | 会話で伝えた誕生日・記念日に、ボットからお祝いを投稿する |
| 返信の評価 | 返信に付く 👍👎 を、モデル・ペルソナ別に集計する（閲覧は管理者のみ） |
| モデレーション | NG ワードと AI 判定で不適切な発言を検知し、3 回でブロックする |
| サーバーごとの設定 | 設定はサーバーごとに独立し、DB に保存されて再起動後も維持される（DM は全 DM で共有） |
| 使い方ガイド | `/functions` → ❓ 使い方 でいつでも説明を表示する。招待されたときにも案内を 1 回投稿する |
| 利用グラフ | Gemini のトークン使用量の推移をグラフで表示する |

## 🛠️ セットアップ

Windows と Linux（Ubuntu など）の両方で動作します。

### 1. 事前準備

- **Python 3.10 以上**
- **Discord Bot トークン**（[Discord Developer Portal](https://discord.com/developers/applications) で取得）
- **Gemini API キー**（[Google AI Studio](https://aistudio.google.com/app/apikey) で取得）
- **Opus 共有ライブラリ**（Linux で読み上げを使う場合のみ。手順 4）
- **日本語フォント**（Linuxでグラフを使う場合。手順 7の「日本語グラフのフォント」）

> **FFmpeg は不要です。** 読み上げの音声変換は、Python パッケージの `miniaudio` がプロセス内で行います。

### 2. Python と仮想環境の準備

**Windows**: [python.org](https://www.python.org/downloads/) から Python をインストールし（「Add python.exe to PATH」にチェック）、プロジェクトのフォルダで実行します。

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

**Ubuntu / Debian**: `venv` は Python 本体と別のパッケージなので、一緒に入れます。

```bash
sudo apt update
sudo apt install -y python3 python3-pip python3-venv
python3 -m venv .venv
source .venv/bin/activate
```

> 仮想環境は必須ではありませんが、システムの Python を汚さないため推奨します。`sqlite3` と `venv` は標準ライブラリなので、`pip install` は不要です。

### 3. パッケージのインストール

仮想環境を有効にした状態で実行します。

```bash
pip install -r requirements.txt
```

直接依存の確認対象版は `requirements.txt` で固定しています。Python 3.10と3.13で共通に導入できる版を使い、更新時はWindows／LinuxのCIを確認します。推移依存まで固定する完全なロックではないため、CIは `pip freeze --all` の結果を環境別の成果物として保存します。手元の導入結果は `python -m pip freeze --all` と `python -m pip check` で確認できます。

旧SDKを使っていた環境を更新するときは、新しい仮想環境へこの依存一覧を導入して検証してください。Geminiは `google-genai`、PDF検証は `pypdf` を使います。APIキーの設定名と既存の `.env` はそのまま利用できます。SDKの変更点は[Googleの移行ガイド](https://ai.google.dev/gemini-api/docs/migrate)、PDFの名称変更は[pypdfの公式履歴](https://pypdf.readthedocs.io/en/stable/meta/history.html)を参照してください。

### 4. Opus ライブラリのセットアップ（Linux のみ）

ボイスチャンネルでの読み上げ（`/join`・自律行動）に必要です。読み上げを使わない場合は省略できます。Windows は discord.py が DLL を同梱しているため不要です。

```bash
sudo apt install -y libopus0
```

> ⚠️ **`discord.py` は必ず `[voice]` 付きで入れてください**（`requirements.txt` では指定済み）。Discord は 2026年3月2日からボイスの E2E 暗号化（DAVE）を必須にしており、対応パッケージの `davey` が無いと `/join` が `RuntimeError: davey library needed in order to use voice` で失敗します。この場合は `pip install "discord.py[voice]"` で解消します。

### 5. APIキーの設定（`.env`）

APIキーは**プロジェクトルート直下の `.env`** に書きます（`src/` の中ではありません）。見本をコピーし、`=` の右側を実際のキーに書き換えます。

```bash
cp .env.example .env    # Windows (PowerShell) では Copy-Item .env.example .env
```

```bash
API_KEY_GEMINI=（Google AI Studio で取得したキー）
TOKEN_DISCORD=（Discord Developer Portal で取得したトークン）
```

- `=` の前後に空白を入れないでください（クォートは不要です）。
- `.env` は `.gitignore` 済みです。実際のキーを見本の `.env.example` に書かないでください。
- キーが未設定（ファイルが無い・値が空・見本のまま）だと、`キー未設定` と表示して**起動を止めます**。
- OS の環境変数に同名のキーがあれば、そちらが優先されます（systemd の `EnvironmentFile=` などでも渡せます）。

#### 既に稼働している環境から移行する場合（ver0.1.5 以前からの更新）

ver0.1.5 以前の `index/config_private.py` から `.env` を自動で作れます。このファイルは Git 管理外のため、`src/` への改名後も旧フォルダ `index/` に残っています。

```bash
python3 deploy/migrate_config_to_env.py             # .env を作る（既にあれば上書きせず中断）
python3 deploy/migrate_config_to_env.py --dry-run   # 書き込まずに取得できるキー名だけ確認（値は表示しない）
python3 deploy/migrate_config_to_env.py --force     # 既存の .env を上書き
```

旧ファイルは import せず構文解析だけで読み、作った `.env` のパーミッションは `600` になります。移行が済んだら、`index/config_private.py` は削除して構いません。

### 6. ボットの起動

```bash
cd src
python bot.py    # Ubuntu で仮想環境を使わない場合は python3
```

`ログイン成功: BotName#0000` と表示されれば起動完了です。**必ず `src/` の中から実行してください**（`bot.py` は引き続き `src/` 直下にあります）。

### 7. 常時稼働の設定（systemd / Linux のみ）

手動で起動した場合はターミナルを閉じると止まり、落ちても自動では復帰しません。Linux サーバーでは systemd に登録してください。見本の `deploy/bot.service.example`（Git 管理対象）から、実際の値を入れた `deploy/bot.service`（Git 管理外）を作って使います。

```bash
cd <PROJECT_DIR>
cp deploy/bot.service.example deploy/bot.service
nano deploy/bot.service                     # <PROJECT_DIR> と <USER> を自分の環境の値に置き換える
sudo cp deploy/bot.service /etc/systemd/system/bot.service
sudo chmod 644 /etc/systemd/system/bot.service
sudo systemctl daemon-reload
sudo systemctl enable --now bot             # 自動起動を有効にして起動する
systemctl status bot                        # "active (running)" なら成功
```

| 操作 | コマンド |
| --- | --- |
| 再起動（コードや `.env` を更新したとき） | `sudo systemctl restart bot` |
| 停止 / 起動 | `sudo systemctl stop bot` / `sudo systemctl start bot`（`stop` した場合は自動で再起動しない） |
| ログを追う / 直近 50 行を見る | `journalctl -u bot -f` / `journalctl -u bot -n 50 --no-pager` |
| ユニットを書き換えたとき | `sudo cp deploy/bot.service /etc/systemd/system/bot.service` → `sudo systemctl daemon-reload` → `sudo systemctl restart bot` |

**運用上の注意**

- `WorkingDirectory` は必ず `src/` にし、`ExecStart` には仮想環境の `python` を絶対パスで書きます（systemd ではシェルの `activate` が効かないため）。
- 再起動の回数制限を外している（`StartLimitIntervalSec=0`）ため、設定ミスがあると**再起動を繰り返し続けます**。`systemctl status bot` が `activating (auto-restart)` のままなら、`journalctl -u bot -n 50` を確認してください。
- `ProtectSystem=strict` や `ProtectHome=yes` は追加しないでください。実行中に `memory/` と `ng/` へ書き込むため、記憶とモデレーションが黙って壊れます。
- 過去に `sudo python bot.py` で動かしたことがあると、`memory/` が root の所有になって書き込めません。`sudo chown -R <USER>:<USER> <PROJECT_DIR>` で直せます。

#### 日本語グラフのフォント

Ubuntu／Debianで利用トークン・会話統計グラフを使う場合は、日本語字形を持つフォントを導入します。

```bash
sudo apt update
sudo apt install -y fonts-noto-cjk
```

候補の順序は `src/persona_bot/config/constants.py` の `GRAPH_FONT_FAMILY` が共通の設定です。Windows用のYu Gothic・Meiryoに続いて、Linuxでも使えるNoto Sans CJK JP・Noto Sans JP・IPAexGothicを選べます。導入済みの候補だけを描画へ渡すため、LinuxでWindows専用フォントを探す警告も抑えます。日本語フォントが1つも無い場合、汎用フォントでの描画は続きますが、日本語は欠落することがあります。

ボットと同じユーザー・仮想環境で、リポジトリルートから解決と実描画を確認します。

```bash
python -B -c "from matplotlib import font_manager; font_manager.findfont(font_manager.FontProperties(family=['Noto Sans CJK JP']), fallback_to_default=False); print('日本語フォント: OK')"
REQUIRE_JAPANESE_GRAPH_FONT=1 python -B -m unittest discover -s tests -p test_graph_fonts.py -v
```

導入後もフォントが見つからない場合は、`python -c "import matplotlib; print(matplotlib.get_cachedir())"` で保存先を確認し、そのフォルダー内の `fontlist-v*.json` だけを退避してから確認コマンドを再実行します。確認後、稼働中のボットを `sudo systemctl restart bot` で再起動してください。

## 🧪 開発時のローカル検証

仮想環境を有効化し、既存の依存関係をインストールした後、リポジトリルートで実行します。

```bash
python -B -m unittest discover -s tests -v
```

APIキーや `.env`、Discord接続、Gemini呼び出しは不要です。外部サービスはモック、一時DB・一時ファイルには架空のデータを使い、実際の `memory/`・`ng/` は変更しません。Windowsでは `.venv\Scripts\python.exe`、Linuxでは `.venv/bin/python` を直接指定しても実行できます。

DBの初期化・設定保存と復元、文書処理の異常系、会話リセット、リマインダー登録・記憶更新の並行処理、生成中の設定変更、コメントの流量制限、JSON保存の中断、長いリマインダー一覧を検証します。`message_handler.py` は起動処理を実行せずimportでき、実際のメッセージ処理へモックを注入してテストします。

[回帰テストCI](.github/workflows/tests.yml) はWindows／LinuxとPython 3.10／3.13で、依存関係・構文・回帰テストを自動確認します。詳しい手順は[貢献ガイド](CONTRIBUTING.md#完全ローカルで確認する)を参照してください。

#### ⚙️ キャラ設定

| メニュー | 選択肢 |
| --- | --- |
| 👤 ペルソナ | ツンデレ / ヤンデレ / メイド / ロリ / ショタ / オジサン / ギャル / メスガキ / お姉さん / はんなり / クレーマー / 標準 |
| 🤖 AIモデル | Gemini 2.5 Flash / Gemini 3.5 Flash / Gemini 3.1 Flash Lite |
| 💬 応答モード | すべての発言に反応 / メンションのみに反応（既定） |

- 「確定」を押すまで反映されません。「🔄 会話リセット」を押すと、そのチャンネルの会話履歴がそこで区切られます。
- 設定はサーバーごとに独立し、DB に保存されて再起動後も維持されます（DM は全 DM で共有。会話リセットの位置は再起動で消えます）。

#### 📈 会話統計 / 👍 フィードバック

- 集計するのはボットへの発言だけです。話題と性格は Gemini による推定で、24 時間キャッシュします。性格推定は、発言が 10 件未満だと表示しません。
- 一般ユーザーは自分の統計だけを、**管理者**は他のメンバーの統計・発言回数ランキング・👍 フィードバックの集計も見られます（すべて本人だけに表示）。
- **👍 フィードバック**: チャット返信に付く 👍👎 を押すだけで評価が記録されます（ボットは返信しません）。連投が続くと自動では付かない返信もありますが、自分で押せば記録されます。返信の相手以外の評価も数えます。文書の返信・自発的な会話・記念日・リマインダーは対象外です。
- 集計で「誰が押したか」は表示しません。評価できるのは直近 500 件の返信までで（再起動でリセット）、記録は 2000 件を超えると古いものから消えます。`FEEDBACK_ENABLED = False` で機能ごと止められます。

#### 🔒 統計プライバシー

- 「📊 統計収集」を OFF にして確定すると、以降の発言は記録されず、AI による推定も行いません。**溜まったデータは残る**ので、消すときは「🗑️ 蓄積データを削除」を 2 回押します。
- 設定は本人専用で、全サーバー共通です。停止していることは他の人には分かりません（管理者のユーザー選択やランキングからも外れます）。
- 対象は会話統計だけで、会話の記憶は消えません。新しいユーザーの既定値は `STATS_OPT_OUT_DEFAULT`（`False` ＝収集する）です。

#### 💬 自発会話

「ボットが自分から話し出す」2 つの機能をまとめたパネルです（どちらも既定は OFF）。無会話しきい値（1・3・6・12・24 時間）は両方で共用し、自律行動で配信している間はテキストへの話題提供を止めます。

- **💬 自発的な会話**: ボットが会話したことのあるテキストチャンネル（DM を除く）が対象です。しきい値の時間だけ会話が無いと、チャンネルの履歴をもとに話題を振ります（長期記憶は使いません）。一度投稿したら、誰かが発言するまで同じチャンネルには投稿しません。対象のチャンネルの一覧は再起動でリセットされます。

#### 🎙️ 自律行動（ボイス/ステージでの「配信」）(BETA)

1. **話したいゲージ**（0〜100）が、会話の無い時間に応じて溜まります（しきい値の時間で 100%。直近の発言が多いと最大 +30%）。
2. 100% になると、**ステージチャンネルを優先**して通話に入ります。ステージでは「会話相手募集中…」の配信枠を自分で開きます。
3. 第一声のあと、3 分ごとに独り言を投稿して読み上げます。そのチャンネルのチャットへの書き込みには、**メンション無しで**応答します（画像にも反応）。
4. コメントが 30 分途絶えるか、配信が 3 時間に達すると、締めの一言を残して退出します。

**止め方**: `/leave`（すぐに退出）、またはパネルで OFF にして確定（1 分以内に終了）。

- 深夜の 00:00〜05:59 は動きません（配信中なら退出します）。人の発言をまだ観測していないサーバーでも動きません。
- コメントは、直前の応答から 10 秒以上空いていれば必ず応答し、立て込んだときだけ間引きます（`AUTONOMOUS_COMMENT_COOLDOWN_SECONDS`）。
- `/join` で呼ばれている間は配信を始めません。別のチャンネルへ移動させられたら配信を終えます。開始に失敗したときは、30 分〜最長 4 時間待ってから再挑戦します（パネルで確定すると待ち時間を解除）。
- コメントには従来どおりモデレーションが掛かります。独り言と第一声には AI モデレーションを掛けず、NG ワードの伏せ字化だけを行います。コメントへの応答に長期記憶は使いません。
- 必要な権限: ステージは「メンバーをミュート」（配信枠を自分で開くにはさらに「チャンネルの管理」「メンバーの移動」）、ボイスは「表示」「接続」「発言」「メッセージを送信」。調整値は `src/persona_bot/config/constants.py` の `AUTONOMOUS_*` にあります。

#### 🎂 記念日・誕生日の自動お祝い

パネルもコマンドもありません。会話で「誕生日は5月1日」のように伝えると、記憶を整理するときに記録され（`memory/profile.json` に手書きして再起動しても登録できます）、当日にお祝いを投稿します（`Asia/Tokyo` 基準。確認は 1 時間ごと）。

- 投稿先は、そのユーザーがいるサーバーの自発会話の対象チャンネル（直近に会話があったもの）です。DM は対象外です。
- 同じお祝いを同じ日に二度投稿することはありません（再起動しても）。文面に長期記憶の中身は使いません。

#### ⏰ リマインダー

コマンドではなく会話で登録します。繰り返し（毎日 / 毎週 / 毎月）も会話から読み取ります。

```
@ボット 毎朝7時に薬を飲むってリマインドして
→ ⏰ 2026年8月13日（水）07:00 に「薬を飲む」をお知らせします。（以後 毎日 くり返します）

（その時刻に、依頼したチャンネルで）
→ ⏰ @あなた リマインダーです: **薬を飲む**
   🔁 次回は 2026年8月14日（木）07:00 にお知らせします。
```

- 「30分後」「明日の朝」などの表現は、`Asia/Tokyo` の現在時刻を基準にボットが解釈します。**確認メッセージの日時が意図どおりか確かめてください。**
- 通知は依頼したチャンネルに届きます（私的な内容は DM で頼んでください）。最大 1 分遅れることがあります。
- 1 人 20 件までです（繰り返しは取り消すまで枠を使い続けます）。過去の日時や 1 年より先の日時は登録できません。取り消しは「⏰ リマインダー」パネルから行います。
- 「知らせて」「リマインドして」など、通知を頼む言葉が必要です。登録された発言には通常の返信をしません。ファイルを添付すると文書の処理が優先されます。
- ボットの停止中に過ぎた通知は、24 時間以内のものだけを起動後に送ります。繰り返しは過ぎた回をまとめて送らず、次回を未来の時刻に設定し直します。存在しない日付（1月31日の翌月など）は、その月の末日に通知します。

#### 🚫 ブロック解除 / ❓ 使い方

- **🚫 ブロック解除**（管理者のみ）: 三審制でブロックされたユーザーを選んで解除し、違反回数をリセットします。
- **❓ 使い方**: 会話のしかたと全機能の説明を表示します。新しいサーバーに招待されたときも、使い方の要点を 1 回だけ投稿します（投稿先はシステムチャンネル → 送信できる最初のテキストチャンネルの順。メンションは飛ばしません。`WELCOME_MESSAGE_ENABLED = False` で止められます）。

### `/join`

実行した人がいるボイスチャンネルにボットを接続します。**接続している間だけ**、AI の返信を読み上げます。

- URL・コード・メンション・Markdown の記号は読み上げません。200 文字を超える分は「以下省略します。」で打ち切ります（`TTS_MAX_CHARS`）。
- 読み上げ中に届いた返信は、最大 5 件まで順番待ちします（`TTS_QUEUE_MAX`）。
- 声はペルソナごとに変わります（男性の話者はオジサン / クレーマー / ショタ。`VOICE_PROFILES` で調整）。edge-tts が使えないときは gTTS に切り替わり、キャラクターごとの声の違いは失われます。

### `/leave`

ボイスチャンネルから退出します。自律行動の配信中なら、配信枠を閉じてから退出します（緊急停止を兼ねます）。

#### 自律行動（ボイス/ステージでの「配信」）

ボットが**自分の意志でボイス/ステージチャンネルへ入り**、「会話相手募集中…」と人を誘って独り言を始める機能を追加しました。従来の「ユーザーの入力に答える」受け身の振る舞いから一歩進めて、ボットの側から会話の場を作りにいきます。デフォルトは OFF で、`/functions` → 💬 自発会話 の 🎙️ 自律行動 トグルから有効化します。

- **話したいゲージ**（サーバーごと・0〜100）: 無会話時間に比例して増え、**無会話しきい値**の時間で 100% に到達する。直近3時間の発言数に応じて最大 +30% 加点され、人が集まっているサーバーほど早く出たくなる。現在値はパネルにバーで表示される（`autonomous_service.compute_talk_desire`）
- **ステージ優先で出ていく**: 発言者になれるステージチャンネルがあればそちらへ、無ければボイスチャンネルへ（候補が複数あればランダム）。ステージでは配信枠（Stage Instance）を自分で開き、トピックを「会話相手募集中…」にして人を誘う。権限は `/join` と同じくチャンネル単位で確認し、入っても喋れないチャンネルは候補から外す
- **配信者としての振る舞い**: 第一声 → `AUTONOMOUS_TALK_INTERVAL_MINUTES`（既定3分）ごとの独り言 → コメントへの応答。いずれもチャンネル付属のチャットへ投稿し、同じ内容を読み上げる。コメントは**その配信チャンネルのチャットからのみ**受け付け、メンションは不要（他のテキストチャンネルからの発言はコメントとして扱わない）。画像だけのコメントにも通常のチャットと同じように反応する
- **コメントの流量制限**: ローカルNG判定の後、入力AIより前に配信単位で受付枠を確保する。直前の受付から `AUTONOMOUS_COMMENT_COOLDOWN_SECONDS`（既定10秒）未満は、同じユーザーの連投も含めて入力判定・生成・出力判定を呼ばない。AIで拒否した入力も枠を消費し、NGワード判定だけで拒否した入力は消費しない。見送ったコメントのAI違反は記録しないが、ローカルNG判定と活動観測は維持する。0以下で制限を解除できる
- **停止条件**: コメントが30分途絶える／深夜（00:00〜05:59）に入る／最長3時間に達する／パネルで無効化する／別のチャンネルへ移動させられる／`/leave` を実行する。いずれも締めの一言を残し、自分で開いた配信枠だけを閉じてから退出する（他人が開いた枠には手を触れない）
- **開始失敗時のバックオフ**: 権限不足などで配信を開始できなかった場合、次に試すまで待ち時間を置く（30分 → 連続失敗で最長4時間）。これが無いと「話したいゲージ」が満タンのままなので、毎分ずっと接続→失敗→切断を繰り返してしまう。パネルで確定すると待ち時間は解除される
- **既存の「自発的な会話」と統一**: ON/OFF の入口を `/functions` → 💬 自発会話 パネルに集約し、しきい値も共用する。両方 ON でも同時には発火せず、**配信中はテキストへの話題提供を止める**
- **モデレーションの方針**: ユーザーのコメントには従来どおりフィルターを掛け、**ボットの自発発言（第一声・独り言）には AI モデレーションを掛けない**（NGワードのマスクのみ）。ペルソナの表現を損なわず、発言のたびの Gemini 呼び出しも増やさないための意図的な非対称
- **プライバシーと安全性**: コメント応答に長期記憶を渡さない（共有の場である配信で個人の記憶を読み上げないため。親密度の更新と 👍👎 の登録も行わない）。ステージ開始時のサーバー全体通知（`send_start_notification`）は使わず、自発発言の投稿はメンション通知を無効化する。人間の発言をまだ観測していないサーバーでは動かない（招待直後・再起動直後にいきなり入り込まないため）
- **新規ファイル**: `src/persona_bot/services/autonomous_service.py`。調整値は `constants.py` の `AUTONOMOUS_*` に集約

#### 設定 UI の変更

- **自発会話パネルを「ボットが自分から話し出す機能」の1枚に**: `AutoTopicView` に 🎙️ 自律行動 トグルを追加し、💬 自発的な会話 と並べた。入口が2か所に分かれるとどちらを切ったのか分からなくなるため統一している（機能ハブの5行は既に使い切っており、ボタンを足す余地が無いという事情もある）
- **パネルに現在の状態を表示**: 話したいゲージのバーと、配信中ならそのチャンネル・深夜の抑制時間帯・無応答での退出時間を表示するようにした
- **`/leave` が自律行動の緊急停止を兼ねる**: 配信中に実行すると、配信枠を閉じてセッションを破棄してから退出する。`/join` も同様に、人が呼んだ接続を優先して先に配信を終了させる

#### 内部の変更

- **DBスキーマを v9 へ更新**: `guild_settings` に `autonomous_enabled` 列を追加（起動時に自動適用）。永続化するのは ON/OFF のみで、配信状態とゲージはインメモリのみ（ボイス接続自体が再起動をまたげないため、復元しても意味がない）

- **`send_long_message` に `allowed_mentions` を追加**: ボットが自分から投稿する文面で通知を飛ばさないようにするため
- **`on_message` パイプラインの分岐を追加**: 配信中のチャンネルからの発言はメンション判定を飛ばして「コメント」として扱い、`handle_comment` へ回す。ブラックリスト・NGワード・入力モデレーションの関門は従来どおり通る。モデレーション（AI呼び出し）の間に配信が終わることがあるため、振り分けの直前に配信中かどうかを取り直し、終わっていれば通常のチャットとして処理する
- **`mark_activity` / `is_comment_channel` の引数順を `(channel_id, guild_id)` に統一**: `AutoTopicService` の同名メソッドと逆順だと、同じ `on_message` から並べて呼ぶときに取り違えても型が同じ（int）ため静かに誤動作する
- **配信チャンネルを自発会話の監視対象に登録しない**: 登録すると、配信が終わったあともそのボイスチャンネルのチャットへテキストの話題が投稿され続ける

### ver0.1.5 — 2026/07/31

#### ボイス読み上げの FFmpeg 依存を廃止

読み上げの音声変換を **FFmpeg（外部の実行ファイル）から `miniaudio`（pip パッケージ）へ置き換え**、外部プロセスの起動を伴う依存をなくしました。CPU 1コア・メモリ 1GB 級の小さな VPS（Oracle Cloud の無料枠など）でも動かせるようにするための変更です。

- **仕組み**: gTTS が返す mp3 を `miniaudio` が**メモリ上のまま** 48kHz / ステレオ / 16bit の生 PCM へデコードし、`discord.PCMAudio` で再生する。Discord のボイス送信はこの形式をそのまま受け取れるため、変換用の外部バイナリが不要になる
- **一時ファイルの廃止**: 従来は返信のたびに一時 mp3 を書き出して削除していたが、すべてメモリ上で完結するようになった（ディスク I/O とファイル削除の後始末が不要に）
- **セットアップの簡略化**: Windows は `pip install -r requirements.txt` のみで完結（`ffmpeg.exe` と約 200MB の DLL 群の手動配置が不要に）。Ubuntu は `sudo apt install -y libopus0` のみ（`ffmpeg` パッケージが不要に）
- `paths.py` の `resolve_ffmpeg_executable()` を削除し、`play_tts_response()` から `ffmpeg_path` 引数を除去

#### 読み上げの品質・安定性を改善

- **読み上げキューを追加**: 従来は再生中に届いた返信を**破棄**していたため、会話が続くと大半が読み上げられなかった。ギルドごとの待ち行列（最大 `TTS_QUEUE_MAX` 件）に積んで順番に読み上げるよう変更。ワーカーはキューが空になると自ら終了するため、タスクは常駐しない
- **読み上げテキストの整形**: URL・コードブロック・カスタム絵文字・メンション・Markdown 記号を除去。特に URL は gTTS が1文字ずつ読み上げてしまい極端に長くなるため効果が大きい
- **文字数上限**: 長文の返信でボイスチャンネルを何分も占有しないよう `TTS_MAX_CHARS`（既定 200 文字）で打ち切る
- **タイムアウト**: 音声合成が `TTS_TIMEOUT_SECONDS`（既定 30 秒）で完了しない場合はその返信の読み上げを見送る
- 調整値は `constants.py` の `TTS_*` に集約

#### 長期記憶をユーザー別に完全分離（プライバシー保護）

これまで全ユーザーで1つの記憶スペースを共有していた長期記憶を、`user_id` ごとに完全分離しました。他人の会話ログ・プロフィール・プロジェクト記憶が混ざらなくなります（プライバシー最優先の設計）。`affinity` / `user_stats` に加えて `profile` / `pending_log` / `projects.json` もユーザー別になり、記憶に関わる全データが `user_id` で独立します。

- **`profile` テーブルの複合主キー化**（スキーマ v2→v3）: 主キーを `(user_id, key)` に変更し、読み書きはすべて対象ユーザーの行だけに限定（`WHERE user_id = ?`）
- **`pending_log` に `user_id` 列を追加**: 一時会話ログを発言者ごとに記録
- **`projects.json` のユーザー別化**: `{"_schema":"per_user_v1","users":{user_id:{...}}}` の形で束ね、文書要約も投稿者スライスへ保存
- **記憶圧縮をユーザー単位に**: `pending_log` を持つユーザーを列挙し、**ユーザーごとに個別に**圧縮（他人の会話ログを同じ Gemini 呼び出しに混ぜない）。他ユーザーのスライスには触れない
- **既存データの自動移行**: 導入前の全体共有データ（旧 `profile` 行・`pending_log` の未割当行・`projects.json` の中身）は失わないよう、`LEGACY_MEMORY_OWNER_ID`（`constants.py`）の記憶として自動で引き継ぐ。SQL で担えない旧行の割り当ては `_migrate_legacy_profile_rows`（冪等・別トランザクション）が処理
- **自発的な会話から個人記憶を除外**: 共有チャンネルへの話題提供で特定ユーザーの `profile` を使うと私的情報が他の参加者へ漏れるため、長期記憶を使わずチャンネル履歴のみを材料にするよう変更

#### Gemini API 呼び出しの削減

記憶のユーザー別分離でコストが増えないよう API 呼び出しを削減しました。

- **入力モデレーションと記憶ルーティングの統合**（効果最大）: 対象テキストが同一なので `content_moderator.check_and_route` で1回の呼び出しにまとめ、チャット主経路の毎メッセージ 2回→1回 に削減
- **ルーティングの軽量プレフィルタ**: あいさつ・相槌などの短い定型発言を正規表現で先に弾き、ルーターの LLM を呼ばず `none` を即決（文書ワーカー経路などで有効）
- **ユーザー単位フラッシュの上限化**: 1回のフラッシュで圧縮する人数を `MEMORY_FLUSH_MAX_USERS_PER_RUN`（既定5人）で区切り、一度に大量の呼び出しが走らないよう制御（残りは次回の見回りで処理・レート制限対策）
- **グラウンディング失敗時リトライの切替**: サブモデルでの再試行を `GROUNDING_SUBMODEL_RETRY_ENABLED`（`constants.py`）で無効化でき、失敗時の呼び出しを1回減らせる（既定は品質維持で ON）

#### サーバー（ギルド）ごとの設定分離

これまでプロセス全体で1組しか持てなかったペルソナ・モデル・応答モードなどの設定を、Discord サーバー（ギルド）ごとに独立させました。同じボットを複数のサーバーに招待しても、サーバー A ではツンデレ・サーバー B ではメイド、というように別々の設定で運用できます。

- **`GuildSettings` の新設**（`app_state.py`）: ペルソナ（`current_prompt_file`）・モデル（`current_model_name`）・応答モード（`current_respond_mode`）・Google検索（`grounding_enabled`）・会話リセット地点（`channel_reset_points`）・自発会話の設定と監視状態を `BotState` 直下から `GuildSettings` へ移動。`BotState` は `guild_settings: dict[ギルドID, GuildSettings]` を持ち、`get_guild(guild_id)` が未登録のサーバーをデフォルト値で自動生成する
- **DM は全 DM 共有の1スロット**: DM にはギルドが存在しないため、`BotState.dm_settings`（`guild_id=None` 相当）を共有して使う
- **UI 層をギルド単位に**: `/functions` の実行時に `interaction.guild_id` から設定を解決し、各 View（`FunctionsView` / `SettingsView` / `AutoTopicView` / `SummaryView`）は `BotState` ではなく `GuildSettings` を受け取る。設定変更の影響範囲がそのサーバー内に閉じる
- **`GeminiService` の状態依存を除去**: `generate()` / `summarize_document()` が内部で `BotState.current_model_name` を読んでいたため、呼び出し側が `model_name` を明示的に渡す形に変更（サービス側が「どのギルドの設定か」を知らずに済むようにするため）。ルーターなど固定モデルを使う経路（`stats_service.py` 等）は `ROUTER_MODEL_NAME` を明示的に渡す
- **プロセス全体で共有する状態は `BotState` に残す**: 最終活動時刻・バックグラウンドタスクの起動フラグなど、サーバーに依存しないものは従来どおり
- **設定を DB へ永続化**（スキーマ v3 → v4）: `guild_settings` テーブルを新設し、ペルソナ・モデル・応答モード・Google検索・自発会話の ON/しきい値をサーバーごとに保存する。起動時に `BotState.restore_from_database()`（`bot.py` の `Database` 初期化直後）がメモリへ復元するため、**再起動しても各サーバーの設定が元に戻らない**。DM はギルドIDが存在しないため `DM_SETTINGS_GUILD_KEY`（= `0`）の行として保存する
- **保存のタイミング**: UI で設定を確定した瞬間に `GuildSettings.persist()` が全列を書き込む（差分更新はしない）。保存に失敗してもチャットや UI 操作は止めない（フェイルオープン。変更はインメモリには残る）
- **永続化しないもの**: 会話リセット地点（`channel_reset_points`）と自発会話の監視チャンネル（`auto_topic_channels` / `auto_topic_posted_at`）は「実行時に自然に再構築される一時状態」のため、従来どおりインメモリのみ

#### 記念日・誕生日の記憶と自動お祝い

会話の中で出てきた誕生日・記念日を長期記憶に覚えておき、その日が来たらボットの方からお祝いする機能を追加しました。登録用のコマンドは不要で、普通の会話で伝えるだけで記憶されます。

- **記憶側**: 記憶圧縮（`memory_service._compact_memory`）のプロンプトに、月日が確定できる記念日を `profile` の `anniversaries` キーへ `[{"label": "誕生日", "month": 5, "day": 1}]` の構造化リストとして保存する指示を追加。既存エントリはマージし（同じ `label` は上書き）、単発の予定は記念日として保存しない
- **お祝い側**: `AutoTopicService.run_anniversary_checks()` を新設し、`ANNIVERSARY_CHECK_MINUTES`（既定60分）ごとの見回りで「今日が記念日のユーザー」を検出。そのユーザーが所属するサーバーの自発会話の監視チャンネル（直近に会話があったもの）へ、ペルソナに沿ったお祝いメッセージを投稿する（`build_anniversary_prompt`、`prompting.py`）
- **全ユーザー横断の取得**: 記念日チェックのため `Database.profile_load_all_for_key(key)` を追加（指定キーの値を `{user_id: 値}` で一括取得）
- **二重投稿の防止**: `GuildSettings.anniversary_posted_dates` に「`{user_id}:{label}` → 投稿日」を記録し、同じ記念日を同じサーバーで同日中に二度投稿しない。この記録は `anniversary_posts` テーブルにも保存され起動時に復元されるため、**当日に再起動しても同じお祝いを繰り返さない**。主キーが `(guild_id, user_id, label)` の upsert のため、毎年お祝いしても行は増えない（その記念日の最終投稿日だけが残る）
- **プライバシーと安全性**: 自発的な会話と同じ方針で、生成材料はチャンネル履歴のみ（個人の `profile` は渡さない ＝「今日が記念日」以上の私的情報を共有チャンネルへ出さない）。DM は対象外。NG ワードはマスクし、モデレーションで不適切と判定された場合は謝罪文に差し替えず**投稿自体を見送る**（記念日を晒した上での謝罪は不自然なため）
- **フェイルセーフ**: `anniversaries` は LLM が書き込む自由記述寄りの記憶のため、形式が期待どおりでないエントリは静かにスキップする。「今日」の判定は `ANNIVERSARY_TIMEZONE`（`Asia/Tokyo`）基準

#### リマインダー（会話から自動登録）

「30分後にゴミ出しって知らせて」のように会話で頼むと、その時刻に依頼したチャンネルでメンション付きで知らせる機能を追加しました。記念日と同じく専用コマンドは無く、普通の会話から登録されます。

- **API 呼び出しを増やさない設計**: 日時の解釈は `content_moderator.check_and_route` に相乗りさせ、**モデレーション・記憶ルーティング・リマインダー抽出の3つを1回の Gemini 呼び出しで**まかなう。判定プロンプトには現在日時（曜日つき）を埋め込み、「30分後」「明日の朝」などの相対表現を絶対日時へ直させる
- **通知文は生成しない**: リマインダーは文面の魅力より正確に届くことが重要なため、通知は Gemini を呼ばずテンプレート（`⏰ @ユーザー リマインダーです: 本文`）で組み立てる。NG ワードのマスクのみ適用する（登録時に AI モデレーションを通過済みのため再判定はしない）
- **新設 `reminder_service.py`**: 依頼の検証（日時の解釈・過去/1年より先の拒否・件数上限・本文の切り詰め）、登録、一覧・取り消し、期限到来分の通知を担う
- **DB へ永続化**（スキーマ v4 → v5）: `reminders` テーブル（`status`: `pending`/`done`/`canceled`）を新設し、再起動しても予定が消えないようにした。見回りの絞り込み用に `(status, remind_at)` の索引を張る
- **二重通知の防止**: `reminder_claim_due()` が SELECT と UPDATE を同一トランザクションで行い、期限到来分を `done` に変えてから返す（`queue_tasks` のクレーム方式と同じ）。`REMINDER_CHECK_SECONDS`（既定60秒）ごとの `reminder_loop` から呼ばれる
- **一覧・取り消し UI**: `/functions` に **⏰ リマインダー** パネル（`reminder_view.py`）を追加。表示するのは**本人の予定だけ**で、取り消しは SQL 側でも `user_id` を条件に含めるため他人のものは操作できない
- **登録できなかった場合の扱い**: 日時が過去・解釈不能などで見送った場合は通常のチャット応答へ流す（依頼でない発言を誤って拾った可能性があるため、エラーを返すより会話を続ける方が自然）。逆に登録できた場合は確認メッセージのみを返し、チャット応答は行わない（同じ発言への二重投稿を避けるため）
- **時刻の扱い**: 保存は UTC の ISO 8601（秒精度に統一し、期限判定を文字列比較で行える形）。解釈・表示は `REMINDER_TIMEZONE`（`Asia/Tokyo`）基準

#### 不具合修正・内部整理

- **クリーンな環境で `/join` がボイス接続に失敗する問題を修正**: `requirements.txt` が素の `discord.py` を指定していたため、ボイス接続に必要な `davey` が入らず、`RuntimeError: davey library needed in order to use voice` で失敗していた。Discord が 2026年3月2日から全ボイスチャンネルで **DAVE**（音声・映像のE2E暗号化）を必須化したことによる新しい依存。`discord.py[voice]` 指定に変更して解決した。あわせて、個別記載していた `PyNaCl` を削除（extra 側がバージョン制約 `<1.6` 付きで入れるため、無指定で書くと制約を超えた版が入っていた）
- **バックグラウンド処理が途中で消えることがあった問題を修正**: asyncio のイベントループは実行中のタスクを**弱参照**でしか保持しないため、`asyncio.create_task()` の戻り値を捨てると処理が途中でガベージコレクトされて静かに消えることがあった。強参照を保つ `background.spawn()` を新設し、該当する6箇所（文書処理ワーカー・会話統計の記録・親密度の保存・記憶圧縮×2・ボイス読み上げ）を置き換えた。特に**文書処理ワーカーは常駐コルーチンのため、消えると添付ファイルが二度と処理されなくなる**深刻な経路だった。あわせて、従来は投げっぱなしで失われていたバックグラウンド処理の例外を、処理名つきでログ出力するようにした
- **タイムゾーンが UTC へフォールバックした環境でリマインダーが9時間ずれる問題を修正**: `tzdata` を含まないスリムな Linux 環境では `Asia/Tokyo` の解決に失敗して UTC で代用されるが、統合判定プロンプトには定数の「Asia/Tokyo」がそのまま埋め込まれていたため、**UTC の現在時刻を「日本時間」と偽って AI に渡していた**。実際に解決できたタイムゾーン名を使う `timeutil.timezone_label()` を追加して修正（会話統計グラフの軸ラベルも同様に修正）
- **グラウンディング失敗時にモデル設定が無視される問題を修正** (`gemini_service.py`): Google 検索グラウンディングが失敗しサブモデルでのリトライも失敗した場合、最終フォールバックがユーザー選択モデルではなく `GROUNDING_MODEL_NAME`（`gemini-2.5-flash`）で実行され、**設定と異なるモデルの回答が黙って返っていた**。リトライ中に使うモデルを `effective_model` として分離し、選択モデルを上書きしないよう修正
- **Windows でログ出力によりボットの処理が中断される問題を修正**: 既定のコンソール（cp932）は絵文字を出力できず、ボット名・ユーザーの発言・NG ワード・モデルの応答に絵文字が含まれると `print` の時点で `UnicodeEncodeError` になっていた。起動時に標準出力を UTF-8（変換できない文字は置換）へ設定するようにした
- **停止中に溜まったリマインダーが一斉に通知される問題を修正**: 予定時刻を `REMINDER_STALE_HOURS`（既定24時間）より大きく過ぎたものは通知せず処理済みにする（何時間も前の「10分後に休憩」を今さら知らされないように）
- **文書を添付したリマインダー依頼で文書処理がスキップされる問題を修正**: `on_message` でリマインダーの判定を添付ファイルの処理より後に移した。あわせて、リマインダーを登録した発言も会話統計に記録されるようになった
- **タイムゾーンデータが無い環境でボットが全く応答しなくなる問題を修正** (`content_moderator.py`): リマインダーの日時解釈に使う `ZoneInfo(...)` を `check_and_route` の `try` の外で組み立てていたため、タイムゾーンデータベースを含まない環境（`tzdata` の無いスリムな Linux イメージなど）では `ZoneInfoNotFoundError` が `on_message` まで伝播し、**すべてのメッセージが無応答**になっていた。モデレーションは「API エラー時も会話を止めない」フェイルオープン設計のため、この挙動は設計方針にも反していた。タイムゾーンはインスタンス生成時に一度だけ解決し、失敗時は UTC へフォールバックするよう修正
- **記念日のお祝いがほとんど発火しない問題を修正** (`auto_topic_service.py`): お祝い対象の取得に `guild.get_member()` だけを使っていたが、本ボットは特権インテントの `members` を有効にしていないためメンバーキャッシュはほぼ空で（ボイス接続者などに限られる）、対象者が常に「サーバーのメンバーではない」と判断されていた。キャッシュに無い場合は `fetch_member()` で取り直すよう修正（記念日は多くても1人年1回のため API 呼び出しの増加は無視できる）
- **2月29日生まれが平年に祝われない問題を修正** (`auto_topic_service.py`): 月日の完全一致で判定していたため、2月29日の記念日は4年に3回スキップされていた。平年は2月28日をその代わりとして扱うようにした（日本で年齢計算に用いられる慣行に合わせた）
- **返信できないチャンネルでの無駄な API 呼び出しを削減** (`bot.py`): `on_message` の対応チャンネル種別チェックがモデレーション（Gemini 呼び出し）より後にあったため、結局返信できない発言のために API を1回無駄打ちし、違反警告の `message.reply()` も失敗していた。判定を NG ワードチェックより前へ移動
- **`/join` の失敗原因が分からない問題を修正** (`commands.py`): ボイスチャンネルへの接続失敗を `except Exception` でまとめて握りつぶし、Discord には「接続に失敗しました。」としか返していなかった。真の理由はボットを起動しているターミナルにしか出ないため、利用者からは権限不足・ネットワーク遮断・接続の残存のどれなのか判別できなかった。次のように原因別のメッセージを返すよう修正した
  - **接続前に権限を確認**: `voice_channel.permissions_for(guild.me)` で「接続」権限が無ければ、接続を試みる前に権限設定を促すメッセージを返す（チャンネル個別の権限上書きで拒否されているケースが最も多いため）
  - **`discord.Forbidden`**: 権限不足として案内する
  - **`asyncio.TimeoutError`**: ボイスに必要な UDP がネットワーク側で遮断されている可能性を案内する（テキストは TCP 443 で動くため、ボイスだけ失敗する構成で起きる）
  - **`discord.ClientException`**: 直前の接続が残っている場合など。待つか再起動を案内する
  - **その他の例外**: 例外クラス名とメッセージをそのまま表示し、原因にたどり着けるようにする
- **自動投稿の後処理を共通化**: 自発的な会話と記念日のお祝いで重複していた「感情タグ除去 → NG ワードのマスク → モデレーション」を `AutoTopicService._screen_auto_post` にまとめた（挙動は変更なし）
- **モデレーションの重複を共通化** (`content_moderator.py`): `check()` と `check_and_route()` が API 呼び出し・プロンプトブロック判定・テキスト取得・JSON パースの約80%を重複して持っていたため、共通部分を `_judge()` に集約した（フェイルオープンを含む判定結果は 23 項目のテストで従来と同一であることを確認済み）
- **タイムゾーン解決を共通化** (`timeutil.py` を新設): 会話統計・記念日・リマインダー・モデレーションの4か所で `ZoneInfo` の組み立てと失敗時フォールバックが重複していたため、`resolve_timezone(name, purpose=...)` に集約した。上記の「タイムゾーンデータが無い環境」の不具合は、この重複のうち1か所だけガードが漏れていたことが原因だったため、共通化そのものが再発防止になっている
- **感情タグの正規表現を1か所に集約** (`affinity_service.py`): `[V:X, A:Y]` を扱う正規表現が `bot.py` / `auto_topic_service.py` / `summary_view.py` に3重定義されていた（空白の許容など細かな差異が生まれると、タグがユーザーに露出する不具合に直結する）。`extract_affinity_changes()`（本文とその変化量を返す）と `strip_affinity_tag()`（除去のみ）としてまとめ、3か所から呼ぶようにした（挙動は変更なし）
- 未使用の import を削除

#### 永続化データを SQLite データベースへ移行

`memory/` 配下の構造化データ（`affinity.json` / `user_stats.json` / `queue.json` / `pending_log.txt`）と プロフィール記憶（`profile.json`）を、単一の SQLite データベース `memory/bot.db` に統合しました。SQL 文は新設の `database.py` に集約しています。`projects.json` は LLM が構造を自由に決める記憶のため、従来どおり JSON ファイルのまま扱います。

- **旧データの自動移行**: 初回起動時に旧 JSON / テキストファイルを DB へ取り込み、`<元の名前>.imported.bak` に改名して保全（二重取り込み防止＋バックアップ）
- **profile.json は手書き追加用の受け皿に**: 起動のたびに `profile.json` の中身を DB の `profile` テーブルへ自動マージ（同名キーはファイル側が優先）し、ファイルを `{}` に戻す。**ユーザーが `profile.json` に事実を書き足して再起動するだけで、ボットの記憶へ追加される**
- **スキーマ移行機構**: `PRAGMA user_version` によるバージョン管理を導入。将来列を追加したくなったら `SCHEMA_VERSION` を上げて `_MIGRATIONS` に `ALTER TABLE` 文を1行追記するだけで、既存 DB にも自動適用される
- **クラッシュ耐性の向上**: 書き込みがトランザクションで原子的になり、旧方式の「ファイル全体上書き中のクラッシュでデータ破損」リスクを解消
- **WAL モード**: ボット稼働中でも `sqlite3` CLI などから安全に中身を読める
- **文書キューの堅牢化**: タスクの取得（claim）を SELECT + UPDATE の同一トランザクションで行い、二重取得を構造的に防止

#### 全機能を `/functions` パネルに統合（UI刷新）

`/status`・`/graph`・`/ng_reload`・`/unblock` と後述の会話要約を、単一の `/functions` コマンド（機能ハブ）に統合しました。Discord の View は最大5行までのため1枚のパネルに合体できないので、ボタンで選んだ機能のパネルへ同じメッセージを差し替える方式を採用しています。

- `/functions` を実行すると、本人だけに見える（エフェメラル）ハブパネルが開く
- **⚙️ キャラ設定** / **📋 会話要約** … パネルを開く（同じメッセージが変身）
- **📊 グラフ** / **🔄 NGワード再読込** … その場で実行し、別のエフェメラルメッセージで結果を返す
- **🚫 ブロック解除**（旧 `/unblock`・**管理者専用**） … `ng/blacklist.json` を直接編集せず、ブロック中ユーザーの選択メニューから解除し違反カウントもリセット。管理者以外にはボタン自体を非表示（従来は権限が無い場合に警告を返信していた）
- キャラ設定パネル（旧 `/status`。「設定」から「キャラ設定」にリネーム）を含め、すべてのパネルをエフェメラル化（従来 `/status` は全員に見えていた）
- **🔍 Google検索** トグルをキャラ設定パネルから機能パネル（ハブ）へ移動し、確定操作なしでその場で切り替えられるように
- 各パネルの「キャンセル/閉じる」を「**↩️ 戻る**」に変更し、機能パネルへ戻って別の機能を続けて使えるように
- 旧コマンド `/status`・`/summarize`・`/graph`・`/ng_reload`・`/unblock` を削除し `/functions` に集約

#### チャンネル会話の議事録要約機能を追加

`/functions` → **📋 会話要約** から、テキストチャンネルの会話を発言者名つきの議事録として要約できます。要約はキャラ設定パネルで選択中のモデル・ペルソナを使用し、冒頭と締めだけキャラ口調、本編は正確で中立的な文体で生成します。

- 期間を **1時間 / 12時間 / 1日 / 1週間 / 1か月** から選択
- 表示範囲を「全員に表示」「自分だけ」から選択
- 発言者は表示名（`display_name`）で判別（他の BOT は除外、自ボットは文脈として含める）
- 決定事項・TODO・保留を抽出。Markdown を使わず Discord で読みやすいプレーンテキストで出力
- 対象メッセージが上限（1000件）を超える場合は要約せず自動停止
- 生成結果は感情タグ・見出し記号の除去、NGワードマスク＋AIモデレーションを経て送信

#### ユーザー別会話統計ダッシュボードを追加

`/functions` → **📈 会話統計** から、ユーザーごとの会話傾向をグラフでダッシュボード表示できます。集計対象は「ボットへの発言のみ」で、`handle_chat_message` の直前に fire-and-forget で記録します（失敗してもチャット本体は止めないフェイルオープン設計）。**すべてエフェメラル（非公開）で表示されます。**

- **集計データ**: ユーザーごとに累計発言回数・時間帯別ヒストグラム（`Asia/Tokyo` の「時」に変換した 24 時間分）・直近発言サンプル（50 件のリングバッファ）を記録
- **話題・性格の LLM 解析**: 直近サンプルを Gemini に渡し「よく話す話題」と「ビッグファイブ性格特性」を JSON で推定。結果は 24 時間キャッシュし、TTL 内は再計算しない（呼び出し・パース失敗時は既存キャッシュにフォールバック）
- **項目別グラフ**（matplotlib）: 時間帯＝棒グラフ / 話題＝重み付き横棒 / 性格＝ビッグファイブのレーダーチャート。項目セレクトで「全部 / 時間帯 / 話題 / 性格推定」を切り替え可能
- 性格推定は直近サンプルが 10 件未満のとき「データ不足」として描画をスキップ（推定である旨も明記）
- **権限**: 一般ユーザーは**自分の統計のみ**閲覧可。**管理者のみ**、ユーザー選択メニューで他メンバーの統計を閲覧でき、発言回数ランキング（全体比較）も表示可能
- データは `memory/bot.db` の `user_stats` テーブルに永続化され、`asyncio.Lock` で対象ユーザー1行の保存を直列化（ボット再起動でもリセットされない）
- 調整値（TTL・上限・タイムゾーンなど）は `constants.py` の `STATS_*` に集約

#### 自発的な会話機能を追加

`/functions` → **💬 自発会話** から有効化すると、一定時間会話が無いチャンネルへ、過去の話題をもとにボットの方から話しかけます。

- 無会話しきい値を **1時間 / 3時間 / 6時間 / 12時間 / 24時間** から選択（デフォルト: OFF・6時間）
- 対象はボットが会話に参加したことのあるテキストチャンネル（自動登録。DM は対象外）

- 設定・監視状態はインメモリのみで、ボット再起動でリセットされる（再起動後はデフォルトの OFF に戻る）

不適切な発言を繰り返すユーザーを自動でブロックする三審制のブラックリスト機能を追加しました。
ユーザーの識別にはDiscordの固有ID（スノーフレークID）を使用しており、ユーザー名を変更しても回避できません。
違反データは `ng/blacklist.json` に永続化され、Bot再起動後も維持されます。

- ブロック解除は `ng/blacklist.json` を直接編集して対応

#### 感情・親密度パラメータ（2次元モデル）の導入(BETA)

ユーザーごとの長期的な関係性を示す「親密度」と、短期的な感情変動を示す「機嫌・テンション」のパラメータを導入し、より人間らしい自然な会話の文脈維持が可能になりました。
パラメータは `memory/affinity.json` にスレッドセーフで永続化されます。

- **長期関係（親密度 - Affinity）**: 0〜100（初期値50）。ユーザーの会話が好意的か攻撃的かによって緩やかに変動します。
- **短期感情（機嫌 - Valence / テンション - Arousal）**: それぞれ 0〜100（初期値50）の2次元モデルでその時の感情状態を表現します。
- **時間経過による感情リセット**: 会話のない経過時間に応じて、感情パラメータ（機嫌・テンション）は半減期（30分）モデルで自動的に初期値（50）へ減衰・リセットされます。
- **軽量・高速なタグ方式**: AIに通常のテキストとして返答させ、末尾に `[V:X, A:Y]` のタグを出力させることで、遅延のない最速のレスポンス設計を採用しています（タグはユーザーには非表示）。

- **Bot応答の AI モデレーション追加**: 直接会話での Bot 応答に AI モデレーションチェックが行われていなかった問題を修正。文書処理と同等の安全チェックを通常チャットにも適用
- **モデレーション誤ブロックの修正**: NGワードリスト自体がプロンプトに含まれることで、Geminiの安全フィルタが過剰に発動し `PROHIBITED_CONTENT` で安全な返答もブロックされる問題を修正
- **記憶圧縮モデルの安定化**: 記憶整理時にユーザー選択モデルを使用していたものを固定のルーターモデルに変更し、安定性を向上
- **JSON抽出処理の安全性向上**: 正規表現を非貪欲マッチに変更し、Markdownのコードブロック除去を追加して安全にJSONをパースできるように修正
- **グラフ描画のフォント設定局所化**: matplotlibのフォント設定を `plt.rc_context` で局所化し、他のモジュールへの影響を防止
- **音声読み上げ（TTS）の非同期化**: 再生終了の待機ループを `after` コールバックに変更して非同期化し、一時ファイルの保存先をOSの一時フォルダに変更
- **複数ファイル添付時のバグ修正**: 複数の文書を添付した際にBotがファイルの数だけ回答を繰り返すバグを修正。要約抽出のみをループし、応答は一度だけ行うようリファクタリング

### ver0.1.2 — 2026/07/07

#### 長期記憶システムを追加

Discord ボットの記憶処理をカテゴリ分割・ルーティング型に刷新しました。

判定に失敗した場合は `none` として安全側に倒し、`pending_log.txt` が一定量を超えるか長時間アイドルのときにバックグラウンドで圧縮・統合します。

- 回答後に会話ログを `pending_log.txt` へ非同期追記

- 圧縮失敗時は JSON を上書きせず、`pending_log.txt` を保持してフェールセーフ動作

- `attachment.size` による事前サイズ検証で、大きすぎるファイルを先に門前払い
- 対応拡張子は `pdf / txt / csv / md` に限定し、未対応ファイルを即座に拒否
- ワーカー側で文書を一時保存し、検証後に Gemini へアップロードして要約を抽出
- 圧縮済み要約を `projects.json` の `document_summaries` に保持し、最終回答のコンテキストに再利用
- `genai.delete_file()` とローカル一時ファイル削除で、処理後の残存物を確実に破棄

### ver0.1.1 — 2026/06/29

#### コマンドいらずの会話

`/ai` コマンドなしで、チャンネルへの通常の発言に直接反応するようになりました。`/setting` コマンドで「すべての発言に反応」と「メンションのみに反応」の2つのモードを切り替えられます。

- **すべての発言に反応**（デフォルト）: チャンネルのメッセージすべてに返答
- **メンションのみに反応**: `@Bot` でメンションしたときだけ返答

#### マルチモーダル対応

メッセージに画像を添付すると、テキストと合わせて Gemini に送信され、画像の内容を踏まえた返答が得られます。

- テキストなしで画像のみ添付した場合は、自動的に「この画像について説明・反応してください。」というプロンプトで処理されます
- 複数枚の画像も一度に送信可能です
- 対応形式: JPEG・PNG などの一般的な画像形式（`image/*` 全般）

#### 会話リセット

`/reset` コマンドでチャンネルの会話履歴をリセットできます。
リセット後は、それ以前の発言を参照せずに新しい文脈で会話を始めます。
リセットポイントはチャンネルごとに独立しており、ボット再起動でクリアされます。
