# Persona Chat in Discord

## 🛠️ 技術スタック

![Python](https://img.shields.io/badge/Python-3.10%2B-3776AB?style=for-the-badge&logo=python&logoColor=white)

Google Gemini AI を活用した Discord ボットです。
テキストチャット・ボイスチャット読み上げ・ペルソナ切り替え・利用状況グラフ表示などの機能を備えています。

> **⚠️ フィクションに関する免責事項**
>
> 本プロジェクトに含まれるペルソナ（キャラクター設定）は、すべて**架空のフィクションキャラクター**です。
> 各プロンプトファイルに記載された性格・口調・行動パターンは、エンターテインメント目的のロールプレイ指示であり、
> 実在の人物・団体・属性を表現・差別・攻撃する意図は一切ありません。
> 本ボットの出力はすべて AI による創作であり、開発者の個人的な見解や主張を反映するものではありません。

## 🛠️ セットアップ

### 1. 事前準備

以下を用意してください。

- **Python 3.10 以上**
- **Discord Bot トークン**（[Discord Developer Portal](https://discord.com/developers/applications) で取得）
- **Gemini API キー**（[Google AI Studio](https://aistudio.google.com/app/apikey) で取得）
- **Opus 共有ライブラリ**（後述。**Linux のみ**、ボイス読み上げを使う場合に必要。Windows は不要）

> **FFmpeg は不要です。** 読み上げの音声変換は Python パッケージの `miniaudio` がメモリ上で行うため、外部の実行ファイルを別途インストールする必要はありません。

> **Windows** と **Linux（Ubuntu 等）** の両方で動作します。以下の手順は OS ごとに分けて記載しています。

---

### 2. Python と仮想環境の準備

**Windows:**

[python.org](https://www.python.org/downloads/) から Python 3.10 以上をインストールします（インストーラーの「Add python.exe to PATH」にチェックを入れてください）。

```powershell
# プロジェクトのフォルダで実行
python -m venv .venv
.venv\Scripts\Activate.ps1
```

**Ubuntu / Debian（何もインストールされていない状態から）:**

```bash
sudo apt update
# Ubuntu では venv が Python 本体と別パッケージのため、個別に入れる必要がある
sudo apt install -y python3 python3-pip python3-venv
```

```bash
# プロジェクトのディレクトリで実行
python3 -m venv .venv
source .venv/bin/activate
```

> **`sqlite3`（データベース）と `venv`（仮想環境）は Python の標準ライブラリ**のため、`pip install` は不要です（`requirements.txt` にも含まれていません）。Ubuntu では上記の `python3` / `python3-venv` パッケージに含まれています。
>
> 仮想環境（venv）は必須ではありませんが、システムの Python を汚さずに済むため推奨します。有効化するとプロンプトの先頭に `(.venv)` が表示されます。

---

### 3. パッケージのインストール

仮想環境を有効化した状態で実行してください。

```bash
pip install -r requirements.txt
```

個別に指定する場合:

```bash
pip install discord.py google-generativeai gTTS miniaudio PyNaCl httpx matplotlib numpy Pillow PyPDF2
```

---

### 4. Opus ライブラリのセットアップ（Linux のみ）

ボイスチャンネルでの読み上げ（`/join`）にのみ必要です。**使わない場合はスキップできます**（読み上げだけが動作せず、チャット機能は通常どおり動きます）。

**Windows:**

**何もする必要はありません。** discord.py が Opus の DLL を同梱しており、自動で読み込まれます。

**Ubuntu / Debian:**

```bash
sudo apt install -y libopus0
```

> **なぜこれだけで済むのか:** Discord のボイス送信は「48kHz / ステレオ / 16bit の PCM」か「Opus 圧縮済みデータ」しか受け付けません。本ボットは gTTS が返す mp3 を `miniaudio`（C ライブラリを同梱した pip パッケージ）で**メモリ上のまま PCM へ変換**し、その PCM を discord.py が `libopus` で Opus へエンコードして送信します。
>
> かつて使っていた FFmpeg は「任意の音声形式 → PCM」の変換を担う**外部の実行ファイル**で、返信のたびに別プロセスとして起動していました。`miniaudio` はこれを同じ Python プロセス内で行うため、**実行ファイルの配置も、プロセス起動のオーバーヘッドも不要**になっています。`libopus` / `PyNaCl` も同様に「プロセス内から呼ばれる共有ライブラリ」であり、外部プロセスは一切起動しません。CPU 1コア・メモリ 1GB 級の小さな VPS（Oracle Cloud の無料枠など）でも動かせる構成です。
>
> なお `PyNaCl`（ボイス通信の暗号化に必要）は libsodium を同梱した wheel のため、`pip install -r requirements.txt` だけで完結し、追加のインストールは不要です。

---

### 5. APIキーの設定

`index/config.py` に、以下の内容を記述してください:

```python
API_KEY_GEMINI = "YOUR_GEMINI_API_KEY"
TOKEN_DISCORD  = "YOUR_DISCORD_BOT_TOKEN"
```

---

### 6. ボットの起動

```bash
cd index
python bot.py
```

`ログイン成功: BotName#0000` と表示されれば起動完了です。

> **必ず `index/` の中から実行してください。** モジュールが互いを名前で参照しており、プロンプトのパスも `index/` を基準に解決されるためです。
> 仮想環境を有効化していない Ubuntu では、`python` ではなく `python3 bot.py` を使ってください。

## 💬 コマンド一覧

### `/functions`

各種機能をまとめた「機能パネル」を開きます。パネルは**本人だけに見える（エフェメラル）**状態で表示され、ボタンで各機能に切り替わります。各パネルは120秒で自動的にタイムアウトします。

> Discord の UI は最大5行までのため1枚に合体できません。選んだ機能のパネルへ**同じメッセージを差し替える**方式を採用しています。各パネルの「**↩️ 戻る**」ボタンで機能パネルへ戻れます。

| ボタン            | 機能                                                                          |
| ----------------- | ----------------------------------------------------------------------------- |
| ⚙️ キャラ設定     | キャラ設定パネルに切り替え（ペルソナ・モデル・応答モード・会話リセット）       |
| 📋 会話要約       | 会話要約パネルに切り替え（期間・表示範囲を選んで議事録を生成）                 |
| 📈 会話統計       | 会話統計パネルに切り替え（発言回数・時間帯・話題・性格推定をグラフ表示）       |
| 💬 自発会話       | 自発会話パネルに切り替え（自発的な話題提供の ON/OFF・無会話しきい値を設定）   |
| ⏰ リマインダー   | リマインダーパネルに切り替え（自分の予定を一覧・取り消し）                     |
| 📊 グラフ         | 利用トークン数の推移グラフをその場で表示                                      |
| 🔄 NGワード再読込 | NGワードリストを再起動なしで再読み込み                                        |
| 🔍 Google検索     | Google検索グラウンディングの ON/OFF をその場で切り替え（デフォルト: ON）      |
| 🚫 ブロック解除   | ブロック中ユーザーの選択メニューから解除（**管理者のみ表示**）                |

#### ⚙️ キャラ設定

**操作方法：**

1. 「⚙️ キャラ設定」を押すと、現在の設定と3つのセレクトメニュー・各種ボタンが表示されます
2. セレクトメニューから変更したい項目を選択します（複数の項目を変更可能。選択結果はメニュー内に即反映されます）
3. 「**確定**」ボタンを押すと設定が反映されます
4. 「**↩️ 戻る**」ボタンを押すと変更は破棄され、機能パネルに戻ります
5. 「**🔄 会話リセット**」ボタンを押すと、そのチャンネルの会話履歴がリセットされます

※ Google検索グラウンディングの ON/OFF は機能パネルの「🔍 Google検索」ボタンで切り替えます。
※ ここで変更した設定（ペルソナ・モデル・応答モード）と会話リセット地点は、**そのサーバー専用**です。同じボットを複数のサーバーに招待しても互いに影響しません。DM では「すべての DM で共有される設定」が使われます。
※ ペルソナ・モデル・応答モードは DB に保存され、**再起動後も維持されます**（会話リセット地点は再起動でリセットされます）。

**セレクトメニュー：**

| メニュー      | 選択肢                                                                                                   |
| ------------- | -------------------------------------------------------------------------------------------------------- |
| 👤 ペルソナ   | ツンデレ / ヤンデレ / メイド / ロリ / ショタ / オジサン / ギャル / メスガキ / お姉さん / はんなり / クレーマー / 標準 |
| 🤖 AIモデル   | Gemini 2.5 Flash / Gemini 3.5 Flash / Gemini 3.1 Flash Lite                                              |
| 💬 応答モード | すべての発言に反応 / メンションのみに反応（デフォルト）                                                  |

#### 📋 会話要約

そのチャンネルの会話を、発言者名つきの議事録として要約します。

1. 「📋 会話要約」を押すと、期間ドロップダウン・表示範囲トグル・「要約実行」ボタンが表示されます
2. **期間**（1時間 / 12時間 / 1日 / 1週間 / 1か月）を選択します
3. **表示範囲**（🌐 全員に表示 / 🔒 自分だけ）をトグルで切り替えます
4. 「**要約実行**」で議事録を生成します（🌐 のときはチャンネルに投稿、🔒 のときは本人だけに表示）

※ 要約はキャラ設定パネルで選択中のモデル・ペルソナを使用します。対象メッセージが 1000 件を超える場合は自動停止します。

#### 📈 会話統計

ユーザーごとの会話傾向を、**本人だけに見える（エフェメラル）**ダッシュボードで表示します。集計対象は「ボットへの発言のみ」です。

1. 「📈 会話統計」を押すと、項目セレクト（全部 / 時間帯 / 話題 / 性格推定）とグラフが表示されます
2. 表示できる内容は次の通りです
   - **時間帯**: よく話す時間帯の発言回数ヒストグラム（`Asia/Tokyo` 基準の 24 時間）
   - **話題**: 直近の発言から推定した「よく話す話題」の重み付き横棒グラフ
   - **性格推定**: 直近の発言から推定したビッグファイブ性格特性のレーダーチャート

※ 話題・性格は Gemini による推定で、結果は 24 時間キャッシュされます。性格推定は発言が 10 件未満のときは「データ不足」として表示されません。
※ 一般ユーザーは**自分の統計のみ**閲覧できます。**管理者のみ**、他メンバーの統計や発言回数ランキング（全体比較）も閲覧できます。

#### 💬 自発会話

一定時間会話が無いチャンネルへ、ボットの方から過去の話題をもとに話しかける機能です（デフォルト: OFF）。

1. 「💬 自発会話」を押すと、しきい値ドロップダウンと ON/OFF トグル、確定/戻るボタンが表示されます
2. **無会話しきい値**（1時間 / 3時間 / 6時間 / 12時間 / 24時間）を選択します
3. 「**💬 自発的な会話**」トグルで機能の ON/OFF を切り替えます
4. 「**確定**」ボタンを押すと設定が反映されます（押すまで設定は変更されません）

※ 対象は「ボットが会話に参加したことのあるテキストチャンネル」で、自動的に監視対象へ登録されます（DM は対象外）。
※ ボット宛てでない発言もそのチャンネルの「会話」としてカウントされ、会話が活発な間は割り込みません。
※ 一度話題提供したら、誰かが発言するまで同じチャンネルには再投稿しません（沈黙中の連投防止）。
※ 話題はキャラ設定パネルで選択中のペルソナ・モデルと、チャンネル履歴をもとに生成されます（長期記憶はプライバシー保護のため使いません。特定ユーザーの個人記憶を共有チャンネルへ漏らさないため）。
※ 応答モードが「メンションのみに反応」の場合、話題提供への返事にもメンションが必要です。
※ ON/OFF としきい値は DB に保存され、再起動後も維持されます。ただし**監視チャンネルの一覧はリセットされる**ため、再起動後は各チャンネルでボットが再び会話に参加した時点から監視が始まります。
※ 設定はサーバーごとに独立しています（あるサーバーで ON にしても、他のサーバーは OFF のままです）。

#### 🎂 記念日・誕生日の自動お祝い

会話の中で伝えた誕生日・記念日をボットが覚えておき、その日が来ると自分からお祝いしてくれる機能です。**パネルもコマンドもありません** — 普通の会話で「誕生日は5月1日」のように伝えるだけで、長期記憶の圧縮時に自動で記録されます。

※ 記念日は `profile` 記憶の `anniversaries` キーに `[{"label": "誕生日", "month": 5, "day": 1}]` の形で保存されます（`memory/profile.json` に手書きして再起動する方法でも登録できます）。
※ お祝いの投稿先は、そのユーザーが所属するサーバーの**自発会話の監視チャンネル**（直近に会話があったもの）です。自発会話の監視対象が無いサーバーには投稿されません。DM は対象外です。
※ 同じ記念日を同じサーバーで同じ日に二度投稿することはありません。投稿記録は DB に保存されるため、**当日にボットを再起動しても同じお祝いを繰り返しません**。
※ お祝いの文面はキャラ設定パネルで選択中のペルソナ・モデルと、チャンネル履歴をもとに生成されます（自発会話と同じく、長期記憶の中身はプライバシー保護のため使いません）。
※ 「今日」の判定は `Asia/Tokyo` 基準です。見回りは1時間ごとのため、投稿は日付が変わった直後とは限りません。

#### ⏰ リマインダー

指定した時刻に、依頼したチャンネルでボットが知らせてくれる機能です。**登録はコマンドではなく会話で行います。**

```
@ボット 30分後にゴミ出しって知らせて
→ ⏰ 2026年7月27日（月）15:30 に「ゴミ出し」をお知らせします。

（時刻になると、依頼したチャンネルで）
→ ⏰ @あなた リマインダーです: **ゴミ出し**
```

「⏰ リマインダー」ボタンを押すと、**自分の**予定が一覧表示され、セレクトメニューから取り消せます。

※ 「30分後」「明日の朝」などの相対表現は `Asia/Tokyo` の現在時刻を基準に解釈されます。**解釈はボットに任されるため、確認メッセージの日時が意図どおりか必ず確かめてください**（違っていれば取り消して登録し直せます）。
※ 通知先は**依頼したチャンネル**です。共有チャンネルで頼むと通知も全員に見えるため、私的な内容は DM で頼んでください。
※ 通知は最大1分遅れることがあります（1分ごとに期限を確認しているため）。
※ 登録できるのは1人あたり20件までです。また、過去の日時・1年より先の日時は登録されません。
※ 単なる予定の報告（「明日は10時から会議だ」）では登録されません。「知らせて」「リマインドして」など通知の依頼が読み取れる場合のみ登録されます。
※ リマインダーとして登録された発言には、通常のチャット返信は行われません（確認メッセージのみ返ります）。
※ 登録内容は DB に保存されるため、再起動しても消えません。
※ **ボットを停止している間に予定時刻を過ぎた場合**、24時間以内の遅れなら起動後すぐに通知されますが、それより古いものは通知されません（何時間も前の予定が一斉に流れてこないようにするためです）。
※ ファイル（pdf / txt / csv / md）を添付した場合は、リマインダーの登録ではなく**文書の処理が優先されます**。リマインダーは添付なしで頼んでください。

- **🔄 NGワード再読込**: `ng/NG_WORD.txt` を再起動なしで再読み込みします

### `/join`

コマンド実行者が参加中のボイスチャンネルにボットを接続します。

**接続している間だけ**、テキストチャンネルでの AI の返信がそのボイスチャンネルで読み上げられます。接続していないときは読み上げは一切行われません（テキストの返信は通常どおり動作します）。

- 読み上げ対象は AI の返信のみで、ユーザーの発言や `/functions` パネルの表示は読み上げません
- URL・コードブロック・メンション・Markdown の装飾記号は、音声で聞いて意味をなさないため読み上げ前に除去されます
- 長い返信は先頭 200 文字までを読み上げ、以降は「以下省略します。」で打ち切ります（テキストには全文が投稿済みのため。`constants.py` の `TTS_MAX_CHARS` で変更可）
- 読み上げ中に次の返信が届いた場合は待ち行列に積まれ、順番に読み上げられます（最大 5 件。`TTS_QUEUE_MAX` で変更可）

---

### `/leave`

ボットをボイスチャンネルから退出させます。退出後は読み上げも停止します。

## 📋 更新履歴

### ver0.1.5 — 2026/07/31

#### ボイス読み上げの FFmpeg 依存を廃止

読み上げの音声変換を **FFmpeg（外部の実行ファイル）から `miniaudio`（pip パッケージ）へ置き換え**、外部プロセスの起動を伴う依存をなくしました。CPU 1コア・メモリ 1GB 級の小さな VPS（Oracle Cloud の無料枠など）でも動かせるようにするための変更です。

- **仕組み**: gTTS が返す mp3 を `miniaudio` が**メモリ上のまま** 48kHz / ステレオ / 16bit の生 PCM へデコードし、`discord.PCMAudio` で再生する。Discord のボイス送信はこの形式をそのまま受け取れるため、変換用の外部バイナリが不要になる
- **一時ファイルの廃止**: 従来は返信のたびに一時 mp3 を書き出して削除していたが、すべてメモリ上で完結するようになった（ディスク I/O とファイル削除の後始末が不要に）
- **セットアップの簡略化**: Windows は `pip install -r requirements.txt` のみで完結（`ffmpeg.exe` と約 200MB の DLL 群の手動配置が不要に）。Ubuntu は `sudo apt install -y libopus0` のみ（`ffmpeg` パッケージが不要に）
- `paths.py` の `resolve_ffmpeg_executable()` を削除し、`play_tts_response()` から `ffmpeg_path` 引数を除去

#### 読み上げの品質・安定性を改善

- **読み上げキューを追加**: 従来は再生中に届いた返信を**破棄**していたため、会話が続くと大半が読み上げられなかった。ギルドごとの待ち行列（最大 `TTS_QUEUE_MAX` 件）に積んで順番に読み上げるよう変更。ワーカーはキューが空になると自ら終了するため、タスクは常駐しない
- **読み上げテキストの整形**: URL・コードブロック・カスタム絵文字・メンション・Markdown 記号を除去。特に URL は gTTS が1文字ずつ読み上げてしまい極端に長くなるため効果が大きい
- **文字数上限**: 長文の返信でボイスチャンネルを何分も占有しないよう `TTS_MAX_CHARS`（既定 200 文字）で打ち切る
- **タイムアウト**: 音声合成が `TTS_TIMEOUT_SECONDS`（既定 30 秒）で完了しない場合はその返信の読み上げを見送る
- 調整値は `constants.py` の `TTS_*` に集約

#### 長期記憶をユーザー別に完全分離（プライバシー保護）

これまで全ユーザーで1つの記憶スペースを共有していた長期記憶を、`user_id` ごとに完全分離しました。他人の会話ログ・プロフィール・プロジェクト記憶が混ざらなくなります（プライバシー最優先の設計）。`affinity` / `user_stats` に加えて `profile` / `pending_log` / `projects.json` もユーザー別になり、記憶に関わる全データが `user_id` で独立します。

- **`profile` テーブルの複合主キー化**（スキーマ v2→v3）: 主キーを `(user_id, key)` に変更し、読み書きはすべて対象ユーザーの行だけに限定（`WHERE user_id = ?`）
- **`pending_log` に `user_id` 列を追加**: 一時会話ログを発言者ごとに記録
- **`projects.json` のユーザー別化**: `{"_schema":"per_user_v1","users":{user_id:{...}}}` の形で束ね、文書要約も投稿者スライスへ保存
- **記憶圧縮をユーザー単位に**: `pending_log` を持つユーザーを列挙し、**ユーザーごとに個別に**圧縮（他人の会話ログを同じ Gemini 呼び出しに混ぜない）。他ユーザーのスライスには触れない
- **既存データの自動移行**: 導入前の全体共有データ（旧 `profile` 行・`pending_log` の未割当行・`projects.json` の中身）は失わないよう、`LEGACY_MEMORY_OWNER_ID`（`constants.py`）の記憶として自動で引き継ぐ。SQL で担えない旧行の割り当ては `_migrate_legacy_profile_rows`（冪等・別トランザクション）が処理
- **自発的な会話から個人記憶を除外**: 共有チャンネルへの話題提供で特定ユーザーの `profile` を使うと私的情報が他の参加者へ漏れるため、長期記憶を使わずチャンネル履歴のみを材料にするよう変更

#### Gemini API 呼び出しの削減

記憶のユーザー別分離でコストが増えないよう API 呼び出しを削減しました。

- **入力モデレーションと記憶ルーティングの統合**（効果最大）: 対象テキストが同一なので `content_moderator.check_and_route` で1回の呼び出しにまとめ、チャット主経路の毎メッセージ 2回→1回 に削減
- **ルーティングの軽量プレフィルタ**: あいさつ・相槌などの短い定型発言を正規表現で先に弾き、ルーターの LLM を呼ばず `none` を即決（文書ワーカー経路などで有効）
- **ユーザー単位フラッシュの上限化**: 1回のフラッシュで圧縮する人数を `MEMORY_FLUSH_MAX_USERS_PER_RUN`（既定5人）で区切り、一度に大量の呼び出しが走らないよう制御（残りは次回の見回りで処理・レート制限対策）
- **グラウンディング失敗時リトライの切替**: サブモデルでの再試行を `GROUNDING_SUBMODEL_RETRY_ENABLED`（`constants.py`）で無効化でき、失敗時の呼び出しを1回減らせる（既定は品質維持で ON）

#### サーバー（ギルド）ごとの設定分離

これまでプロセス全体で1組しか持てなかったペルソナ・モデル・応答モードなどの設定を、Discord サーバー（ギルド）ごとに独立させました。同じボットを複数のサーバーに招待しても、サーバー A ではツンデレ・サーバー B ではメイド、というように別々の設定で運用できます。

- **`GuildSettings` の新設**（`app_state.py`）: ペルソナ（`current_prompt_file`）・モデル（`current_model_name`）・応答モード（`current_respond_mode`）・Google検索（`grounding_enabled`）・会話リセット地点（`channel_reset_points`）・自発会話の設定と監視状態を `BotState` 直下から `GuildSettings` へ移動。`BotState` は `guild_settings: dict[ギルドID, GuildSettings]` を持ち、`get_guild(guild_id)` が未登録のサーバーをデフォルト値で自動生成する
- **DM は全 DM 共有の1スロット**: DM にはギルドが存在しないため、`BotState.dm_settings`（`guild_id=None` 相当）を共有して使う
- **UI 層をギルド単位に**: `/functions` の実行時に `interaction.guild_id` から設定を解決し、各 View（`FunctionsView` / `SettingsView` / `AutoTopicView` / `SummaryView`）は `BotState` ではなく `GuildSettings` を受け取る。設定変更の影響範囲がそのサーバー内に閉じる
- **`GeminiService` の状態依存を除去**: `generate()` / `summarize_document()` が内部で `BotState.current_model_name` を読んでいたため、呼び出し側が `model_name` を明示的に渡す形に変更（サービス側が「どのギルドの設定か」を知らずに済むようにするため）。ルーターなど固定モデルを使う経路（`stats_service.py` 等）は `ROUTER_MODEL_NAME` を明示的に渡す
- **プロセス全体で共有する状態は `BotState` に残す**: 最終活動時刻・バックグラウンドタスクの起動フラグなど、サーバーに依存しないものは従来どおり
- **設定を DB へ永続化**（スキーマ v3 → v4）: `guild_settings` テーブルを新設し、ペルソナ・モデル・応答モード・Google検索・自発会話の ON/しきい値をサーバーごとに保存する。起動時に `BotState.restore_from_database()`（`bot.py` の `Database` 初期化直後）がメモリへ復元するため、**再起動しても各サーバーの設定が元に戻らない**。DM はギルドIDが存在しないため `DM_SETTINGS_GUILD_KEY`（= `0`）の行として保存する
- **保存のタイミング**: UI で設定を確定した瞬間に `GuildSettings.persist()` が全列を書き込む（差分更新はしない）。保存に失敗してもチャットや UI 操作は止めない（フェイルオープン。変更はインメモリには残る）
- **永続化しないもの**: 会話リセット地点（`channel_reset_points`）と自発会話の監視チャンネル（`auto_topic_channels` / `auto_topic_posted_at`）は「実行時に自然に再構築される一時状態」のため、従来どおりインメモリのみ

#### 記念日・誕生日の記憶と自動お祝い

会話の中で出てきた誕生日・記念日を長期記憶に覚えておき、その日が来たらボットの方からお祝いする機能を追加しました。登録用のコマンドは不要で、普通の会話で伝えるだけで記憶されます。

- **記憶側**: 記憶圧縮（`memory_service._compact_memory`）のプロンプトに、月日が確定できる記念日を `profile` の `anniversaries` キーへ `[{"label": "誕生日", "month": 5, "day": 1}]` の構造化リストとして保存する指示を追加。既存エントリはマージし（同じ `label` は上書き）、単発の予定は記念日として保存しない
- **お祝い側**: `AutoTopicService.run_anniversary_checks()` を新設し、`ANNIVERSARY_CHECK_MINUTES`（既定60分）ごとの見回りで「今日が記念日のユーザー」を検出。そのユーザーが所属するサーバーの自発会話の監視チャンネル（直近に会話があったもの）へ、ペルソナに沿ったお祝いメッセージを投稿する（`build_anniversary_prompt`、`prompting.py`）
- **全ユーザー横断の取得**: 記念日チェックのため `Database.profile_load_all_for_key(key)` を追加（指定キーの値を `{user_id: 値}` で一括取得）
- **二重投稿の防止**: `GuildSettings.anniversary_posted_dates` に「`{user_id}:{label}` → 投稿日」を記録し、同じ記念日を同じサーバーで同日中に二度投稿しない。この記録は `anniversary_posts` テーブルにも保存され起動時に復元されるため、**当日に再起動しても同じお祝いを繰り返さない**。主キーが `(guild_id, user_id, label)` の upsert のため、毎年お祝いしても行は増えない（その記念日の最終投稿日だけが残る）
- **プライバシーと安全性**: 自発的な会話と同じ方針で、生成材料はチャンネル履歴のみ（個人の `profile` は渡さない ＝「今日が記念日」以上の私的情報を共有チャンネルへ出さない）。DM は対象外。NG ワードはマスクし、モデレーションで不適切と判定された場合は謝罪文に差し替えず**投稿自体を見送る**（記念日を晒した上での謝罪は不自然なため）
- **フェイルセーフ**: `anniversaries` は LLM が書き込む自由記述寄りの記憶のため、形式が期待どおりでないエントリは静かにスキップする。「今日」の判定は `ANNIVERSARY_TIMEZONE`（`Asia/Tokyo`）基準

#### リマインダー（会話から自動登録）

「30分後にゴミ出しって知らせて」のように会話で頼むと、その時刻に依頼したチャンネルでメンション付きで知らせる機能を追加しました。記念日と同じく専用コマンドは無く、普通の会話から登録されます。

- **API 呼び出しを増やさない設計**: 日時の解釈は `content_moderator.check_and_route` に相乗りさせ、**モデレーション・記憶ルーティング・リマインダー抽出の3つを1回の Gemini 呼び出しで**まかなう。判定プロンプトには現在日時（曜日つき）を埋め込み、「30分後」「明日の朝」などの相対表現を絶対日時へ直させる
- **通知文は生成しない**: リマインダーは文面の魅力より正確に届くことが重要なため、通知は Gemini を呼ばずテンプレート（`⏰ @ユーザー リマインダーです: 本文`）で組み立てる。NG ワードのマスクのみ適用する（登録時に AI モデレーションを通過済みのため再判定はしない）
- **新設 `reminder_service.py`**: 依頼の検証（日時の解釈・過去/1年より先の拒否・件数上限・本文の切り詰め）、登録、一覧・取り消し、期限到来分の通知を担う
- **DB へ永続化**（スキーマ v4 → v5）: `reminders` テーブル（`status`: `pending`/`done`/`canceled`）を新設し、再起動しても予定が消えないようにした。見回りの絞り込み用に `(status, remind_at)` の索引を張る
- **二重通知の防止**: `reminder_claim_due()` が SELECT と UPDATE を同一トランザクションで行い、期限到来分を `done` に変えてから返す（`queue_tasks` のクレーム方式と同じ）。`REMINDER_CHECK_SECONDS`（既定60秒）ごとの `reminder_loop` から呼ばれる
- **一覧・取り消し UI**: `/functions` に **⏰ リマインダー** パネル（`reminder_view.py`）を追加。表示するのは**本人の予定だけ**で、取り消しは SQL 側でも `user_id` を条件に含めるため他人のものは操作できない
- **登録できなかった場合の扱い**: 日時が過去・解釈不能などで見送った場合は通常のチャット応答へ流す（依頼でない発言を誤って拾った可能性があるため、エラーを返すより会話を続ける方が自然）。逆に登録できた場合は確認メッセージのみを返し、チャット応答は行わない（同じ発言への二重投稿を避けるため）
- **時刻の扱い**: 保存は UTC の ISO 8601（秒精度に統一し、期限判定を文字列比較で行える形）。解釈・表示は `REMINDER_TIMEZONE`（`Asia/Tokyo`）基準

#### 不具合修正・内部整理

- **バックグラウンド処理が途中で消えることがあった問題を修正**: asyncio のイベントループは実行中のタスクを**弱参照**でしか保持しないため、`asyncio.create_task()` の戻り値を捨てると処理が途中でガベージコレクトされて静かに消えることがあった。強参照を保つ `background.spawn()` を新設し、該当する6箇所（文書処理ワーカー・会話統計の記録・親密度の保存・記憶圧縮×2・ボイス読み上げ）を置き換えた。特に**文書処理ワーカーは常駐コルーチンのため、消えると添付ファイルが二度と処理されなくなる**深刻な経路だった。あわせて、従来は投げっぱなしで失われていたバックグラウンド処理の例外を、処理名つきでログ出力するようにした
- **タイムゾーンが UTC へフォールバックした環境でリマインダーが9時間ずれる問題を修正**: `tzdata` を含まないスリムな Linux 環境では `Asia/Tokyo` の解決に失敗して UTC で代用されるが、統合判定プロンプトには定数の「Asia/Tokyo」がそのまま埋め込まれていたため、**UTC の現在時刻を「日本時間」と偽って AI に渡していた**。実際に解決できたタイムゾーン名を使う `timeutil.timezone_label()` を追加して修正（会話統計グラフの軸ラベルも同様に修正）
- **グラウンディング失敗時にモデル設定が無視される問題を修正** (`gemini_service.py`): Google 検索グラウンディングが失敗しサブモデルでのリトライも失敗した場合、最終フォールバックがユーザー選択モデルではなく `GROUNDING_MODEL_NAME`（`gemini-2.5-flash`）で実行され、**設定と異なるモデルの回答が黙って返っていた**。リトライ中に使うモデルを `effective_model` として分離し、選択モデルを上書きしないよう修正
- **Windows でログ出力によりボットの処理が中断される問題を修正**: 既定のコンソール（cp932）は絵文字を出力できず、ボット名・ユーザーの発言・NG ワード・モデルの応答に絵文字が含まれると `print` の時点で `UnicodeEncodeError` になっていた。起動時に標準出力を UTF-8（変換できない文字は置換）へ設定するようにした
- **停止中に溜まったリマインダーが一斉に通知される問題を修正**: 予定時刻を `REMINDER_STALE_HOURS`（既定24時間）より大きく過ぎたものは通知せず処理済みにする（何時間も前の「10分後に休憩」を今さら知らされないように）
- **文書を添付したリマインダー依頼で文書処理がスキップされる問題を修正**: `on_message` でリマインダーの判定を添付ファイルの処理より後に移した。あわせて、リマインダーを登録した発言も会話統計に記録されるようになった
- **タイムゾーンデータが無い環境でボットが全く応答しなくなる問題を修正** (`content_moderator.py`): リマインダーの日時解釈に使う `ZoneInfo(...)` を `check_and_route` の `try` の外で組み立てていたため、タイムゾーンデータベースを含まない環境（`tzdata` の無いスリムな Linux イメージなど）では `ZoneInfoNotFoundError` が `on_message` まで伝播し、**すべてのメッセージが無応答**になっていた。モデレーションは「API エラー時も会話を止めない」フェイルオープン設計のため、この挙動は設計方針にも反していた。タイムゾーンはインスタンス生成時に一度だけ解決し、失敗時は UTC へフォールバックするよう修正
- **記念日のお祝いがほとんど発火しない問題を修正** (`auto_topic_service.py`): お祝い対象の取得に `guild.get_member()` だけを使っていたが、本ボットは特権インテントの `members` を有効にしていないためメンバーキャッシュはほぼ空で（ボイス接続者などに限られる）、対象者が常に「サーバーのメンバーではない」と判断されていた。キャッシュに無い場合は `fetch_member()` で取り直すよう修正（記念日は多くても1人年1回のため API 呼び出しの増加は無視できる）
- **2月29日生まれが平年に祝われない問題を修正** (`auto_topic_service.py`): 月日の完全一致で判定していたため、2月29日の記念日は4年に3回スキップされていた。平年は2月28日をその代わりとして扱うようにした（日本で年齢計算に用いられる慣行に合わせた）
- **返信できないチャンネルでの無駄な API 呼び出しを削減** (`bot.py`): `on_message` の対応チャンネル種別チェックがモデレーション（Gemini 呼び出し）より後にあったため、結局返信できない発言のために API を1回無駄打ちし、違反警告の `message.reply()` も失敗していた。判定を NG ワードチェックより前へ移動
- **`/join` の失敗原因が分からない問題を修正** (`commands.py`): ボイスチャンネルへの接続失敗を `except Exception` でまとめて握りつぶし、Discord には「接続に失敗しました。」としか返していなかった。真の理由はボットを起動しているターミナルにしか出ないため、利用者からは権限不足・ネットワーク遮断・接続の残存のどれなのか判別できなかった。次のように原因別のメッセージを返すよう修正した
  - **接続前に権限を確認**: `voice_channel.permissions_for(guild.me)` で「接続」権限が無ければ、接続を試みる前に権限設定を促すメッセージを返す（チャンネル個別の権限上書きで拒否されているケースが最も多いため）
  - **`discord.Forbidden`**: 権限不足として案内する
  - **`asyncio.TimeoutError`**: ボイスに必要な UDP がネットワーク側で遮断されている可能性を案内する（テキストは TCP 443 で動くため、ボイスだけ失敗する構成で起きる）
  - **`discord.ClientException`**: 直前の接続が残っている場合など。待つか再起動を案内する
  - **その他の例外**: 例外クラス名とメッセージをそのまま表示し、原因にたどり着けるようにする
- **自動投稿の後処理を共通化**: 自発的な会話と記念日のお祝いで重複していた「感情タグ除去 → NG ワードのマスク → モデレーション」を `AutoTopicService._screen_auto_post` にまとめた（挙動は変更なし）
- **モデレーションの重複を共通化** (`content_moderator.py`): `check()` と `check_and_route()` が API 呼び出し・プロンプトブロック判定・テキスト取得・JSON パースの約80%を重複して持っていたため、共通部分を `_judge()` に集約した（フェイルオープンを含む判定結果は 23 項目のテストで従来と同一であることを確認済み）
- **タイムゾーン解決を共通化** (`timeutil.py` を新設): 会話統計・記念日・リマインダー・モデレーションの4か所で `ZoneInfo` の組み立てと失敗時フォールバックが重複していたため、`resolve_timezone(name, purpose=...)` に集約した。上記の「タイムゾーンデータが無い環境」の不具合は、この重複のうち1か所だけガードが漏れていたことが原因だったため、共通化そのものが再発防止になっている
- **感情タグの正規表現を1か所に集約** (`affinity_service.py`): `[V:X, A:Y]` を扱う正規表現が `bot.py` / `auto_topic_service.py` / `summary_view.py` に3重定義されていた（空白の許容など細かな差異が生まれると、タグがユーザーに露出する不具合に直結する）。`extract_affinity_changes()`（本文とその変化量を返す）と `strip_affinity_tag()`（除去のみ）としてまとめ、3か所から呼ぶようにした（挙動は変更なし）
- 未使用の import を削除

#### 感情・親密度パラメータ（2次元モデル）の導入(BETA)

ユーザーごとの長期的な関係性を示す「親密度」と、短期的な感情変動を示す「機嫌・テンション」のパラメータを導入し、より人間らしい自然な会話の文脈維持が可能になりました。
パラメータは `memory/affinity.json` にスレッドセーフで永続化されます。

- **長期関係（親密度 - Affinity）**: 0〜100（初期値50）。ユーザーの会話が好意的か攻撃的かによって緩やかに変動します。
- **短期感情（機嫌 - Valence / テンション - Arousal）**: それぞれ 0〜100（初期値50）の2次元モデルでその時の感情状態を表現します。
- **時間経過による感情リセット**: 会話のない経過時間に応じて、感情パラメータ（機嫌・テンション）は半減期（30分）モデルで自動的に初期値（50）へ減衰・リセットされます。
- **軽量・高速なタグ方式**: AIに通常のテキストとして返答させ、末尾に `[V:X, A:Y]` のタグを出力させることで、遅延のない最速のレスポンス設計を採用しています（タグはユーザーには非表示）。

## ⚠️ 注意事項

- **`bot.py` を起動している IDE やターミナルを終了するとボットが停止します。** 運用時はサーバーやバックグラウンド実行を検討してください。
